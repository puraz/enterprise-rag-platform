# 检索评估黄金集

## 这是什么

A11 的验收硬要求："每加一个节点用同一批 20+ query 做加前加后对比，数据说话"。
没有黄金集就无法回答"加 rerank 到底提升了多少 recall"。

## 结构

- `corpus/` —— 用于建库的源文档（Markdown）
- `queries.jsonl` —— 每行一个 `EvalCase`
- `run_eval.py` —— 建库 + 跑检索 + 出指标报告

## 为什么是"人工标注的期望片段"而不是"期望答案"

评估检索质量只需要知道**哪段原文应该被召回**，不需要标准答案。
用"期望答案"评估的是生成质量（那是 A15 的事），混在一起会让
"检索没召回"和"模型答错"无法区分。

`relevant_snippets` 填的是**原文里的字符串片段**（精确匹配），
因为分块策略会变（边界不同），用"第几个 chunk"做标注在换策略后全失效。
用原文片段做标注则跨策略稳定——脚本按"chunk 是否包含该片段"判定命中。
